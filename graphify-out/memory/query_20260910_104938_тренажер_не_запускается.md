# Q: тренажер не запускается

## Answer

Expanded from original query via graph vocab: [app, application, build, file, grade, lesson, package, trainer, window, windows, запуск, тренажёр]. Runtime verification of the F package showed exit code -1073740771 and Windows .NET Runtime event 1026 with System.DllNotFoundException before the main window appeared. The publish directory contained five native WPF DLLs missing from the transferred folder. Added StudentWin64.pubxml with IncludeNativeLibrariesForSelfExtract=true, rebuilt, tested from a clean folder containing only EXE, Lessons and instruction, then replaced the F copy. The real main window now opens and responds with no new Application errors.

## Outcome

- Signal: corrected
- Correction: The earlier hidden-process smoke was insufficient: it only observed a process briefly and did not confirm a WPF main window. A valid package check must require a nonzero MainWindowHandle/title and no new Windows Application/.NET Runtime errors from a clean delivery folder.
